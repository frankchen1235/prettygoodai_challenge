# Architecture

This system is a Python voice-bot test harness that calls the Pretty Good AI assessment line through Twilio and uses an OpenAI Realtime session to play the role of a realistic patient. A scenario YAML file defines the patient persona, goal, constraints, success criteria, and bug checks. The CLI creates an outbound Twilio call, Twilio requests TwiML from the local FastAPI app, and Twilio Media Streams connect the live call audio to a WebSocket bridge. The bridge forwards inbound `audio/x-mulaw` phone audio to OpenAI Realtime as `g711_ulaw`, streams generated patient audio back to Twilio, and writes per-call artifacts including metadata, transcripts, summaries, and MP3 recordings.

The key design choices prioritize safety, auditability, and realistic conversations. The CLI hard-guards the destination so it can only call `+18054398008`, preventing accidental calls to unrelated numbers. Scenarios are goal-based instead of fixed scripts so the patient can handle interruptions and clarifying questions naturally while still covering appointment scheduling, rescheduling, cancellation, refill, general information, and edge-case flows. The bridge waits for the called agent to speak first and avoids clearing queued Twilio audio, which makes the recordings easier to review. A deterministic local evaluator then reads the saved transcripts and summaries to produce `BUG_REPORT.md` and `artifacts/eval_report.json`, so each reported issue can be traced back to a specific call artifact.
